# Final Hardened-Beta Acceptance

The final candidate is accepted only after all packet completion contracts and Appendix V are proven.

## Daily-driver journeys

1. Clean install and first local scan.
2. Upgrade/import real R15.3 owner data and restart.
3. Search local and providers; play immediately.
4. Like/save/add to duplicate-supporting playlist.
5. Play, shuffle, rapid Next/Previous, queue move/remove, system controls.
6. Download, restart, disconnect, play offline, remove cache/download separately.
7. Scanner sees managed download without duplicate Recording.
8. Identify ugly local track, receive metadata/artwork, Undo, edit override, restart.
9. Last.fm disconnected invisibility; connect and scrobble local/provider/download; offline outbox.
10. Lyrics rapid skip and offline cache.
11. Crew stable matrix or explicit experimental gate.
12. Process death/checkpoint restore and route changes.
13. Light/dark/dynamic color, TalkBack, large text, reduced motion, small/large screens.
14. Backup/export and restore.
15. Signed release update path and rollback instructions.

## Final review classifications

- **Release blocker:** wrong identity/state, data loss, migration/cutover failure, playback mismatch, severe offline/provider failure, ANR/crash, security/privacy, inaccessible core journey, unmet Appendix V stable claim.
- **Near-term refinement:** non-blocking polish/performance/edge case safe for beta with explicit issue.
- **Post-beta cleanup:** internal simplification or optional enhancement that does not weaken daily-driver truth.

## No false completion

A candidate is not beta-ready because code volume is large, all packets are marked implemented, or unit tests are green. It is beta-ready when the integrated release build and user data prove the contract.
